# Verification Guide

Every material verification should include:
- `V-xxx`
- related `SR-xxx`
- related `T-xxx`
- method
- setup/preconditions
- steps/abuse case
- expected result
- pass criteria
- fail criteria
- evidence
- execution status

Status:
- NOT RUN
- PASS
- FAIL
- BLOCKED

Default is NOT RUN.

Never report PASS without execution evidence.

Evidence may include logs, packet captures, screenshots, CI artifacts, firmware hashes, crash dumps, analysis reports, fuzzing evidence, or tester sign-off.
