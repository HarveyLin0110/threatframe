# Compliance / Assurance Mapping

Use `CM-xxx` for compliance/framework mappings.

Compliance mapping is downstream of threats, mitigations, and security requirements.

Examples:
- IEC 62443
- CRA
- NIST/internal security baselines
- Customer requirements

Record:
- CM ID
- Related T/M/SR
- Framework
- Requirement identifier
- Mapping Status
- Rationale
- Source/version
- Verified date
- Evidence

Use:
- `Verified Mapping`
- `Candidate Mapping`
- `Not Mapped`

Do not:
- Use compliance requirements as a substitute for threat discovery.
- Invent normative text.
- Claim compliance/certification from threat-model output alone.
