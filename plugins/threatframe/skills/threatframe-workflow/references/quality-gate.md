# Quality Gate

Before finalizing:

## Product Context
- Product profiles reflect the actual product.
- Network Device profile is used for network appliances where relevant.
- Industrial/OT is not applied merely from marketing/deployment assumptions.

## Core Model
- Scope/mode stated.
- Unknowns/assumptions visible.
- Architecture/DFD uses known facts only.
- STRIDE is systematic but not forced.
- Attack paths represent real multi-step scenarios.
- Multi-layer impact is used when relevant.
- Existing controls are evidence-backed.
- Risk has rationale/confidence.

## Engineering
- Mitigation and security requirement are separate.
- Requirements are testable.
- Verification has expected result, pass/fail criteria, evidence, and truthful status.
- Residual risk is explicit.

## Knowledge Mapping
- Knowledge source was selected for a reason.
- CAPEC/ATT&CK/CWE are not forced.
- IDs/names are not invented.
- Candidate vs Verified is explicit.
- Version/live-version and verified date are recorded where applicable.
- CWE is used only when a plausible weakness exists.

## Compliance
- Compliance mappings use CM IDs.
- No compliance/certification claim is made from threat modeling alone.

Use PASS / INCOMPLETE / N/A.
